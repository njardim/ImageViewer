# GEMINI.md — ImageViewer

**Read `docs/PLAN.md` first.** It is the single source of truth: current status (§1), decision log (§2), architecture (§6), fidelity criteria (§7), phases with checkboxes (§9), and pending decisions (§13). Do not re-derive decisions recorded there; do not re-open them without new evidence.

## What this is
Cross-platform (Windows, macOS, Linux) image viewer in **C++20 + Qt 6.12**, minimalist UI, **verifiable colour fidelity in SDR and HDR**, format coverage ≥ qView ∪ ImageGlass ∪ FFmpeg image2. Owner: Nuno Jardim (Cristallumnis). **Open source under Apache-2.0** (decision D-18): `LICENSE` + `NOTICE` ship in every package; the Cristallumnis trademark is not licensed; future Cristallumnis AI modules are separate proprietary plugins (open core); contributions need a DCO sign-off.

## Rules
- **Language (D-27): everything in the repository is 100 % English** — code, identifiers, comments, UI source strings, docs, commit messages, PR texts. Nothing in Portuguese is committed (the Portuguese UI lives only in `translations/imageviewer_pt.ts`). Talk to the user in the language they write in (Nuno: European Portuguese).
- **Names (D-59):** technical names (Zoom) and proper names ("Windows icon", "Animated PNG", format and decoder names) stay as written in every language: never through `tr()`.
- **Closed development (D-59):** until public downloads begin, every version is installed as if for the first time: no code or tests that migrate settings from earlier versions.
- **UI text (D-27):** every user-visible string goes through `tr()` (QObject classes) or `QCoreApplication::translate("Context", …)`; numbers through `QLocale`; never build sentences from translated fragments (join complete segments outside `tr`); add a `//:` translator comment when a string carries syntax (`&&`, `;;`, units). After changing UI strings: `cmake --build <dir> --target update_translations`, translate the 36 languages (D-32), run `tests/check_translations.py`. `--info`/`--render` output stays English (tests parse it).
- **Who writes the code (D-37):** application code, tests and build scripts are written by the main session's model; never delegate code to a less capable model (subagents for code or reviews run on the same model). Less capable models may only translate `translations/*.ts`.
- **Keep the structure minimal** (decision D-08): one executable target, flat `src/`, one `CMakeLists.txt`. Split a file only when it exceeds ~800 lines. No new directories or abstraction layers without a recorded decision. `packaging/` (D-20) holds vcpkg overlays, third-party licence texts, the CI licence gate and the application's icons (`packaging/icons`, made by `scripts/make_icons.py`, D-66) — never application code. `translations/` (D-27) holds the Qt Linguist `.ts` files. `ViewerWindow` is split in `viewer.cpp` (window, rendering, view state, input), `navigation.cpp` (folder, loading, preloading, folder watching, recent files) (D-33), `overlays.cpp` (information panel, top overlay, navigation buttons) (D-34), `commands.cpp` (command table, menus, dialogs) (D-30), `files.cpp` (file operations), `playback.cpp` (animation, slideshow) (D-41), `gallery.cpp` (the gallery, D-60) and `input.cpp` (keyboard, mouse, wheel); the renderer is `renderer.cpp` and `offscreen.cpp` (render to a texture and read back, for the harness); the preload cache is `cache.{h,cpp}` (D-33); `settings.cpp` holds the preferences and `settingsdialog.cpp` the Settings dialog; `openwith.{h,cpp}` lists and starts the system's applications for a file (D-53). Decoding (D-38, D-41): `formats.{h,cpp}` (registry), `decoders.{h,cpp}` (OpenImageIO, shared helpers), `qtimage.cpp` (what Qt decodes: the registry's Qt formats; an SVG only from memory, with every reference outside the document removed, D-71; and `OiioImagePlugin`, the Qt image plugin that reads the PNG, JPEG, GIF and WebP images inside SVG, ICNS and cursor files through OpenImageIO, D-68; its metadata is `imageplugin.json`), `codecs.cpp` (libjxl, libwebp, Softimage PIC), `apng.cpp`, `heif.cpp` (AVIF sequences), `syscodecs.cpp` (the system's HEIC decoders) and `worker.cpp` (the GraphicsMagick decode worker, the only file that includes GraphicsMagick).
- **Never copy code from qView or ImageGlass** (GPL-3). They are behavioural references only (D-11): we offer their good features (D-28, parity matrix in `docs/PLAN.md` §8.1) designed and written our own way.
- **Commands (D-30):** a user action is one `ViewerWindow::Command`: add it to `commands()` (shortcuts), `commandText()`, `isCommandEnabled()`, `execute()` and to the right submenu in `showContextMenu()`. Keyboard and menus then stay in sync.
- **Settings (D-29):** a new preference is a `Settings` field with a default, validated in `Settings::load()`, saved in `save()`, editable in `SettingsDialog`. Numbers move by one of two steps (D-61): sizes and percentages by `Settings::kSizeStep` (`sizeBox`, `sizeValue`), times by `Settings::kTimeStepMs` (`secondsBox`, `timeValue`); ranges and defaults sit on the step. `Settings::loop` is the only "after the last image" option. Tests that launch the GUI set `XDG_CONFIG_HOME` (and `HOME`/`XDG_DATA_HOME` when they delete) to a temporary directory.
- **Licences:** only LGPL (dynamically linked) or permissive dependencies (GPL is incompatible with shipping under Apache-2.0). Excluded: exiv2, FFmpeg `gpl`/`nonfree`, x265, LibRaw GPL packs, Ghostscript, PyQt.
- **Colour pipeline invariant:** decoders output native depth + colour descriptor + **straight alpha** (D-21); conversion to **linear scRGB (RGBA16F, premultiplied)** happens once on the CPU; the shader only does exposure, tone mapping, compositing over the background in linear light and output encoding (ScRGB / PQ / SdrIcc). Never quantize below FP16 before output. Descriptor priority: CICP > ICC > format attributes > assumed (D-22).
- **Releases** (D-19, D-26): versions are X.Y[-suffix], never X.Y.Z; the version comes from the tag. Publishing a GitHub release `vX.Y[-suffix]` (or pushing the tag) builds, verifies and attaches the packages; nobody builds release binaries by hand.
- **Dependencies (D-46):** every library at its latest stable release; check versions against upstream at the start of each release and before its PR (vcpkg's baseline lags upstream). The check is automated (D-62): label an issue "auto update", or run `python3 scripts/update_dependencies.py` (report only; `--apply` edits the pins). Qt's version lives in `packaging/qt-version.txt`. GraphicsMagick has a prepared path to ImageMagick 7 (D-47). Our patches to a dependency (D-57, D-73) are temporary: each is `packaging/vcpkg/ports/<port>/imageviewer-*.patch` with its header (`Library:`, `Fixes:`, `Upstream:`, `Remove when:`, read by the scripts) and a row in `docs/PLAN.md` §15; at every update, check whether upstream fixed the defect and remove the patch at once. **Supply chain (D-67):** a release is taken only once it is 15 days old, the number in `packaging/cooldown-days.txt` (D-72: the owner may lower it on `main` for a release and sets it back; never change it on your own), except a security fix recorded in `packaging/cooldown-exceptions.txt` after reading its changes (`update_dependencies.py` writes and removes those entries, D-73); every known vulnerability is updated away, patched (`Fixes:`) or assessed in `packaging/known-vulnerabilities.txt`, or the release gate refuses the release; prefer sources fetched from a tag's commit over release archives, and verify an archive against its tag (`scripts/audit_dependencies.py --sources`); a new shipped library goes into `audit_dependencies.py` (every build fails otherwise); the release gate runs `audit_dependencies.py` (vulnerabilities, sources, cooldown); every GitHub Action is pinned by commit; a workflow that runs an AI agent reads only the owner's text. Qt reads only the formats the registry gives it, never by content (its bundled codecs are not audited): the packages carry only the Qt image plugins the registry uses (`build.yml` holds the others back; `scripts/build-qt-linux.sh` removes them), a plugin directory from `QT_PLUGIN_PATH` is ignored (D-75), and the PNG, JPEG, GIF and WebP images inside SVG, ICNS and cursor files go to `OiioImagePlugin` (D-68, D-71); an SVG reaches Qt only after `qtimage.cpp` has removed every reference outside it (D-71); a job that runs third-party code (an AI agent) has no write access to the Actions cache, pins what it installs and gets a read-only token: a separate job without the agent pushes only its `gemini/issue-<n>` branch and opens the pull request, which the owner reviews and merges (D-74). The newest release past the cooldown is pinned, never one below a security fix (D-69). Reports: `SECURITY.md`.
- **The Gemini workflow (D-78):** `.github/workflows/gemini-issue-solver.yml` changes only when the owner asks for it; `GEMINI.md` is kept level with `CLAUDE.md`.
- **Licences in practice:** a dependency that pulls default features can silently override `"default-features": false` in our manifest (that is how x265 got in, D-25); the CI licence gate must stay green.
- **Components over the image (D-60):** every panel, overlay or bar drawn over the image keeps `kEdgeMargin` (16 px) from the window's edges and rounds its corners by `kPanelRadius` (8 px), both in `viewer.h`; a new component uses them, never its own values.
- **Viewer is a `QWindow` with its own QRhi swapchain** (D-09) — Widgets cannot do HDR. Dialogs/menus may use Widgets.
- **Evidence:** when adding claims to the plan, tag them `[code]`, `[doc]`, `[test]`, `[knowledge]` or `[inference]`.

## Before every pull request (D-35)
At the end of each release's development and before opening its PR: a **full adversarial review of the whole codebase** (not only the diff) for bugs, security, performance and badly structured code, by the main session itself, without reviewer agents (owner, 2026-10-16: they cost more usage than they save), every finding reproduced before it is fixed, all tests and CI green again, and the review summarised in the PR. The procedure is in `docs/PLAN.md` §11 ("Before every pull request"). No PR while a confirmed bug or security finding is open.

## End-of-session duty
Update `docs/PLAN.md`: §1 (status, next steps, blockers), §2 (new decisions with date and reason), §9 checkboxes, §13/§14 as needed. Commit it with the code.

## Build
- Production deps via vcpkg manifest (`vcpkg.json`), dynamic triplets; Qt from official binaries (aqtinstall) in CI.
- Local Linux/cloud sessions: `download.qt.io` and GitHub release assets are blocked by the proxy. Build Qt from source with `scripts/build-qt-linux.sh` (installs to `/opt/qt6`), and use Ubuntu apt packages for OIIO/FFmpeg/lcms2 when compiling locally:
  ```
  cmake --preset linux-system && cmake --build --preset linux-system
  ```
- Tests: `tests/smoke.sh <exe>` (headless decode/colour checks), `tests/screen_test.py <exe> [vulkan|opengl]` (Xvfb, on-screen pixel exactness at 100 %), `tests/render_test.py <exe> [vulkan|opengl]` (Xvfb, offscreen render of every output mode vs. the CPU reference `color::applyOutputStage` and the BT.2390 spec), `tests/ui_test.py <exe> [vulkan|opengl]` (Xvfb + xdotool: side zones, flips/rotations, trash with confirmation, saved session), `tests/animation_test.py <exe> [vulkan|opengl]` (animation and slideshow), `tests/fuzz_smoke.py <exe> [mutations]` (every test file corrupted must decode or fail cleanly, D-38), `tests/quit_test.py <app exe>` (macOS only, in CI: quitting from the application menu) and `tests/check_translations.py` (placeholders and completeness of the `.ts` files). Long-tail test files come from `tests/longtail_data.py`, the PQ/HLG corpus from `tests/hdr_corpus.py` (D-65). Local builds without libheif ≥ 1.23 or GraphicsMagick ≥ 1.3.49 skip those checks; CI requires them (`IMAGEVIEWER_REQUIRE_ALL_DECODERS`). Shader and `applyOutputStage` must stay in lockstep. `scripts/build-qt-linux.sh` also builds qttools' `lupdate`/`lrelease` (LinguistTools), qtsvg and qtimageformats into `/opt/qt6`.
- CI: `.github/workflows/build.yml` (Windows x64, macOS arm64, Linux x64).

## Git
Work on the branch the workflow checked out (`gemini/issue-<n>`); commit with clear messages and a DCO sign-off (`git commit -s`); never rewrite its history. Never push and never open a pull request: your token can only read, and the workflow publishes your commits as a pull request on `gemini/issue-<n>` for the owner to review and merge (D-74).
